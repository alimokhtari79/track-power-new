# Cart navigation and language switching

`src/js/cart-state.js` owns the existing cart fixture (OEM 81.30301-0629, quantity 1, price 29,000,000 toman, original price 30,000,000), its existing FA/EN names and assets, quantity validation and totals. `src/js/storefront.js` renders the same snapshot in the homepage preview, mobile cart page and navigation count. No product, rating, second cart line, price, tax or shipping calculation has been fabricated to match the screenshot's sample values. The discount percentage is calculated from actual prices, correcting the old inconsistent 5% badge and unrelated static totals.

The user explicitly selected sessionStorage persistence for this task. Only version and quantity are stored under `trak-power-cart-v1` in the current tab. Language versions use the same key; prices and identity always come from the shared fixture. Invalid/inaccessible storage falls back to in-memory state. Decreasing to zero or removing the item shows an empty state and hides checkout. The original quantity used Persian digits with `Number()`, producing NaN; all calculations now use numeric state and Intl formatting for display. No cross-tab or long-term persistence is added.

At 768px and above, the homepage cart button toggles a preview with quantity controls, original/current subtotal and checkout. It dismisses on outside click, Escape (restoring focus), focus leaving the cart, or crossing the breakpoint. The language disclosure and cart preview are mutually exclusive. Below 768px, the existing bottom navigation structure is shared by both homepages, both cart pages and the Persian categories page. The Cart item opens the existing locale-specific cart URL and receives the active state there. The cart page has a fixed mobile checkout summary above the safe-area-aware bottom bar. Checkout links retain the existing `shopnig-card/shipping.html` destination; shipping/payment mock pricing and actual order processing are outside this change.

Language controls use an explicit map of actual page pairs. Every existing HTML page loads the shared scripts; pages with existing language links reuse that placement, while other pages get a compact language row. Homepages reuse the existing action area when present. The switch retains query parameters and fragments and supports hosting in a subdirectory. `pages/login.html` maps to the case-sensitive `en/pages/Login.html`. The Persian categories page has no English counterpart, so English is disabled there and English bottom navigation marks the Persian categories destination as `(FA)`. No Persian page is relabeled as an English translation. The existing English login/account/dashboard files were already untracked user work: only the two integration script tags are added to them in the working tree, and their full content is deliberately excluded from this task's commit.

The reference's card spacing, rounded white preview, red quantity controls/checkout, green prices, mobile cart active state and two-language popup with flags/active dot are implemented with existing tokens and assets. The reference shows two sample products, while the real existing fixture has only one. Product title and OEM/manufacturer information are retained instead of inventing a spring product or rating. Flag emoji appearance depends on the platform. Mobile cart keeps a compact language icon beside the title so switching remains accessible.

Tailwind output must be built with `npm run dev` and the watcher stopped afterward. Browser visual verification requires permission to access Chrome; if unavailable, state/path tests do not establish pixel accuracy, real native interactions or overflow behavior.
